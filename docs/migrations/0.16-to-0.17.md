# 0.16 → 0.17: deprecate UI-owned annotations

This edge is recorded in [MIGRATIONS.json](../../MIGRATIONS.json). **There is
no runtime removal in 0.17.** The exported `@ponchia/ui/annotations` helpers,
`@ponchia/ui/css/annotations.css`, `.ui-annotation*` selectors and annotation
class recipes remain available through this minor. The earliest intended
breaking removal is **0.18**, after the 0.17 deprecation has shipped and
consumers have a migration opportunity.

## Package ownership

| Responsibility | Owner |
| --- | --- |
| Theme/tokens, UI chrome, figure stage/overlay, generic DOM leader lines | `@ponchia/ui` |
| Note model, anchors, annotation-specific connectors, placement, collision avoidance, editing, renderers and annotation stylesheet | `@ponchia/annotations` |
| Selection, persistence, undo authority, permissions, canvas transforms and lifecycle | Consuming application |

**Neither package imports or re-exports the other.** Keep the UI package
dependency-free. Annotations reads optional Bronto theme tokens through CSS
fallbacks; its core works with no UI package or DOM.

## Migrate a geometry consumer

Install the stable annotation package matching its versioned documentation,
or select a verified release candidate deliberately:

```sh
npm install @ponchia/annotations@0.6.10
```

```ts
// Before:
import { annotationParts, notePlacement } from '@ponchia/ui/annotations';

// After:
import { annotationParts, notePlacement } from '@ponchia/annotations';
```

**Runtime floor:** the published `@ponchia/ui@0.17.0` package supports Node
18+, while the published `@ponchia/annotations@0.6.10` package declares
**Node 20.19+**. This is a real compatibility change for Node 18
applications and build pipelines. Upgrade and verify the consumer runtime
before replacing the UI subpath; do not disguise the difference by re-exporting
the newer package through UI.

The standalone engine includes the legacy geometry helpers, with source
parity checks documented in
[`bronto-ui-annotation-parity.json`](https://github.com/Ponchia/bronto-annotations/blob/main/docs/bronto-ui-annotation-parity.json).
Do not assume all type signatures, higher-level layout policies or results
remain identical without consumer tests. The standalone package additionally
provides `resolveAnnotationLayout`, React/SVG rendering, editing and adapters.

## Migrate CSS and class names

```css
/* Before, from Bronto UI's legacy SVG annotation leaf: */
@import '@ponchia/ui/css/annotations.css';

/* After, standalone package owns presentation: */
@import '@ponchia/annotations/bronto.css';
```

Keep `@ponchia/ui` for application styling or `@ponchia/ui/css/figure.css`
for figure stages. **Do not import both legacy annotation leaves into the same
page**: duplicate selectors can have competing precedence.

`@ponchia/annotations/bronto.css` supports the legacy `.ui-annotation*`
selectors, so old static SVG can migrate stylesheets before migrating markup.
Prefer the package's `.pa-annotation*` classes for new code:

```ts
import { annotationClassName, brontoAnnotationClassName } from '@ponchia/annotations';

annotationClassName({ variant: 'callout', tone: 'accent' });
// 'pa-annotation pa-annotation--callout pa-annotation--accent'
brontoAnnotationClassName({ variant: 'callout', tone: 'accent' });
// legacy: 'ui-annotation ui-annotation--callout ui-annotation--accent'
```

The legacy Bronto `ui.annotation()` recipe and `cls.annotation*` keys remain
through 0.17 so applications can migrate gradually. Port source references
rather than re-exporting them from Bronto UI.

## Avoid indirect duplicate styles

During 0.17, both `@ponchia/ui/css/analytical.css` and
`@ponchia/ui/css/report-kit.css` still include the deprecated annotation leaf
for compatibility. Replacing only a direct `annotations.css` import is not
sufficient if a roll-up also loads it. A migrated consumer should import the
UI leaves it actually uses, rather than these two roll-ups:

```css
@import '@ponchia/ui';
@import '@ponchia/ui/css/report.css';
@import '@ponchia/ui/css/figure.css';
@import '@ponchia/ui/css/dataviz.css';
@import '@ponchia/ui/css/legend.css';
@import '@ponchia/annotations/bronto.css';
```

Add other UI leaves as needed. The default UI bundle itself does not include
annotation CSS. Preserve meaningful contrast, reduced motion, forced colors
and print behavior when reviewing the replacement stylesheet: coverage of
legacy selector names does not establish identical computed styles.

## Installed-package integration proof

The [independent annotations example](https://github.com/Ponchia/bronto-ui/tree/main/examples/annotations-vite)
installs this UI candidate from its packed tarball and Annotations 0.6.10 from
npm. It creates a real annotation, changes its target, hides/restores it,
resizes the shared coordinate space and switches UI themes without any legacy
UI annotation import. Neither library depends on the other. Run:

```sh
npm run test:examples:cross-browser -- annotations-vite
npm run test:examples:visual -- annotations-vite
```

This is first-party installed-package evidence, not an independent-user
acceptance or a replacement for the later application-integration review.

## Acceptance before the removal PR

1. Locate production imports and markup using
   `rg -n 'ui/annotations|css/annotations|ui-annotation|ui\.annotation' src`
   (adjust root for each consumer).
2. Upgrade actual package dependencies and lockfiles; do not rely only on
   checkout-relative aliases or fixture mocks.
3. Verify geometry, overlay alignment and labels at narrow/large viewport
   sizes, changed zoom/pan, dark/light themes and printed output.
4. Verify keyboard and physical touch interaction where annotation editing is
   enabled; passing unit or axe checks are not a substitute.
5. Run the host's permission, persistence, undo/redo, collaboration and
   renderer-lifecycle tests where applicable (including Spatial).
6. Confirm real consumers have migrated and publish 0.17 before scheduling
   0.18's separate BREAKING removal of the public API, CSS, recipes, generated
   exports, deprecated tests and demos.

Generic `@ponchia/ui/connectors` and `initConnectors()` remain independent
UI leader-line primitives; this migration does not delete them.
